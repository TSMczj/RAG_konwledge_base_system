## 0. 使用说明

**任务编号规则**：`T-<阶段>.<序号>`，例如 `T-1.3`。

**复杂度标记**：
| 标记 | 含义 |
|---|---|
| `S` | 单文件、逻辑简单，一气呵成 |
| `M` | 需要设计取舍，可能要调几次才对 |
| `L` | 涉及多模块配合或需要实测调优 |

**状态标记**：`[ ]` 待开始 · `[-]` 进行中 · `[x]` 已完成

**单条任务的完成定义（DoD）**：
1. 代码写完且**能跑通**；
2. 有对应交付物落到指定路径；
3. 满足该条给出的**验收口径**；
4. 该条涉及的可调参数已写入 `.env`，没有硬编码。

## 3. Sprint 1 · 文档摄入与索引（M1）

> **出口标准**：导入 10 份混合格式文档，成功率 ≥ 95%；随机抽 20 个 chunk 人工检查合格；1 个损坏文件不阻断整批。

### 3.1 文档解析（FR-02）

- [x] **T-1.1 加载器抽象层** `M`
  - 交付：`app/core/loader.py`
  - 要求：按扩展名分发到具体解析器；**统一返回结构**（`text`、`metadata`），便于下游一致处理
  - 依赖：T-0.3
  - 验收：新增格式只需加一个函数，不改调用方

- [x] **T-1.2 TXT 加载器** `S`
  - 交付：`loader.py` 中的 txt 分支
  - 要求：`charset-normalizer` 编码探测，默认 UTF-8
  - 依赖：T-1.1
  - 验收：GBK 编码的 txt 也能正确读出中文

- [x] **T-1.3 PDF 加载器（正文）** `M`
  - 交付：PyMuPDF 按页抽取
  - 要求：**每页文本块必须携带页码**
  - 依赖：T-1.1
  - 验收：解析结果能回溯到 `(文件名, 页码)`

- [x] **T-1.4 PDF 表格抽取** `L`
  - 交付：pdfplumber 抽表 → 转 Markdown 表格文本
  - 要求：表格**整体成块**，不与其他正文混切
  - 依赖：T-1.3
  - 验收：用 3 份含表格的真实文档实测，表格未错行错列

- [x] **T-1.5 Word 加载器** `M`
  - 交付：python-docx 解析段落 + 表格（可选 `unstructured` 兜底）
  - 依赖：T-1.1
  - 验收：`.docx` 标题层级与表格都能抽出

- [x] **T-1.6 解析容错与失败清单** `S`
  - 交付：批量解析的 try/except 包裹 + 失败清单输出
  - 要求：**单文件失败不中断整批**
  - 依赖：T-1.1
  - 验收：混入 1 个损坏文件，其余正常入库，失败项被记录

- [x] **T-1.7 扫描件检测告警** `S`
  - 交付：文本层密度检测（对应风险 R1）
  - 要求：密度低于阈值时告警"疑似扫描件，V1 不支持"
  - 依赖：T-1.3
  - 验收：给一个纯图片 PDF，能给出告警而非静默产出空文本

### 3.2 分块（FR-03）

- [x] **T-2.1 分块器** `M`
  - 交付：`app/core/splitter.py`
  - 要求：`RecursiveCharacterTextSplitter`，中文分隔符优先级 `\n\n → \n → 。 → ； → ！ → ？ → ，`，`chunk_size=500` / `overlap=80`（从配置读）
  - 依赖：T-1.1
  - 验收：抽样 20 个 chunk，句子未被从中间截断

- [x] **T-2.2 表格块保护** `S`
  - 交付：表格块绕过二次切分
  - 依赖：T-2.1、T-1.4
  - 验收：表格所在 chunk 未被切散

- [x] **T-2.3 元数据装配** `S`
  - 交付：每个 chunk 注入 `source_file`、`file_path`、`doc_type`、`page`、`chunk_index`、`chunk_id`、`file_hash`
  - 依赖：T-2.1
  - 验收：字段与需求文档 §6.2 Schema 完全一致

### 3.3 向量化与入库（FR-04）

- [x] **T-3.1 Qwen 嵌入客户端** `M`
  - 交付：`app/core/embedder.py`
  - 要求：`text-embedding-v4`、维度 1024、**每批 ≤ 10 条**、超时（连接 10s / 读取 60s）、重试 3 次指数退避
  - 依赖：T-0.3
  - 验收：输入 25 条文本，自动切成 3 批，全部返回 1024 维

- [x] **T-3.2 Chroma 封装** `M`

  - 依赖：T-0.2
  - 验收：进程重启后 `collection.count()` 保持不变

- [x] **T-3.3 幂等去重** `S`
  - 交付：基于文件内容 SHA-256 的判重
  - 依赖：T-3.2
  - 验收：同一文件导入两次，库内块数不变

- [ ] **T-3.4 建库 CLI** `M`
  - 交付：`scripts/build_index.py`
  - 要求：扫描目录 → 解析 → 分块 → 嵌入 → 入库，**打印进度与统计**（文件数、块数、耗时、失败项）
  - 依赖：T-1.6、T-2.3、T-3.3
  - 验收：一条命令把 `data/uploads/` 全部建库

- [ ] **T-3.5 索引管理 CLI** `M` （FR-05）
  - 交付：`scripts/manage_index.py`
  - 要求：列出文档 / 按文件删除 / 全量重建

### 3.4 阶段验收

## 4. Sprint 2 · 检索与生成（M2）

  - 要求：System（只依据上下文、不知道就说不知道、必须标 `[n]`）+ 带编号 Context + Question

  - 验收：每个上下文块都有唯一编号，能与来源元数据一一对应

- [ ] **T-4.3 上下文 Token 控制** `S`
  - 交付：超 `MAX_CONTEXT_TOKENS`（默认 6000）时按相似度截断
  - 依赖：T-4.2
  - 验收：塞入超长上下文不报错，自动截断

- [ ] **T-4.4 DeepSeek 流式客户端** `M` （FR-08）
  - 交付：`app/core/llm.py`
  - 要求：`deepseek-v4-flash`、OpenAI 兼容接口、**流式输出**、`temperature=0.2`、超时与重试

  - 验收：库外问题回复"知识库中没有相关信息"，不编造

- [ ] **T-4.6 问答 CLI** `S`
  - 交付：`scripts/ask.py`

- [ ] **T-4.7 测试集与命中率统计** `M` （验收 A2 的基础）

  - 依赖：T-4.6

- [ ] **T-4.8 ✅ M2 出口验收** `M`
  - 判定：① Top-5 命中率 ≥ 85%；② 抽查 10 条回答可溯源率 100%；③ 兜底不编造；④ 检索 P95 < 1s

## 10. 开发约定

| 项 | 约定 |
|---|---|
| 提交粒度 | **一个任务一次提交**，commit message 带编号，如 `feat(T-1.3): PDF 按页解析` |
| 分支策略 | 单人开发可直接用 `main`；若想稳一点，用 `dev` 分支，阶段验收通过再合 `main` |
| 命名 | 文件/函数 `snake_case`；类 `PascalCase`；常量大写 |
| 配置 | **任何可调值都不许硬编码**，一律进 `.env` / `config.py` |
| 日志 | 关键路径打点（解析耗时、检索耗时、token 用量） |
| 测试 | 涉及外部 API 的一律 mock，测试不花钱 |

## 12. 建议推进批次

| 批次 | 内容 | 说明 |
|---|---|---|
| 第 1 批 | Sprint 0 全部 | 基建，一次做完 |
| 第 2 批 | T-1.1 ~ T-1.3、T-2.1 ~ T-2.3 | 打通"解析→分块" |
| 第 3 批 | T-3.1 ~ T-3.4、T-3.6 | 打通"嵌入→入库"，**M1 验收** |
| 第 4 批 | T-4.1 ~ T-4.8 | 打通"检索→生成"，**M2 验收（准确率定生死）** |
| 第 5 批 | T-1.4、T-1.5、T-1.7 | 补表格/Word/扫描件检测（不挡主流程） |
| 第 6 批 | Sprint 3 全部 | Web 化 |
| 第 7 批 | Sprint 4 全部 | 多轮 + 测试 + 交付 |

> **批次设计逻辑**：把**准确率验证（第 4 批）放在界面开发（第 6 批）之前**。如果检索命中率不达标，此时返工成本最低——还没写任何前端。
